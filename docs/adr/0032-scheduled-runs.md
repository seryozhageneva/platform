# ADR 0032. Запуск пайплайна по расписанию

- **Статус:** принято
- **Дата:** 12.11.2026

## Контекст

В задаче 25 преподаватель получает еженедельную сводку в кабинете. Способ запуска
`schedule` и поле `cron` уже есть в формате графа (ADR 0005). Для выполнения в фоне
есть PostgreSQL и очередь Redis с рабочим процессом arq (ADR 0022).

## Решение

- Один пайплайн может иметь одно расписание из пяти полей cron. Выражение хранится в графе,
  проверяется библиотекой CronSim и читается по часовому поясу `Europe/Moscow`. Образ
  платформы проверяет наличие этого часового пояса при сборке.
- Таблица `schedules` хранит включённость, параметры и последнюю поставленную в очередь
  минуту. После сохранения графа преподаватель включает расписание в редакторе. Если из
  графа убрать этот способ запуска, расписание выключается в той же транзакции.
- Тот же рабочий процесс arq каждую минуту проверяет подходящие записи. Он использует
  последнюю сохранённую версию графа и заново сверяет параметры. Пропущенные минуты
  при возобновлении работы не перебираются. Параметры, которые перестали подходить
  после изменения графа, нужно обновить в редакторе.
- Перед постановкой в очередь рабочий процесс сверяет версию и настройки под блокировкой
  в PostgreSQL. В одной транзакции записывает минуту срабатывания и новый запуск.
  Если Redis не подтвердил приём задания, транзакция откатывается. Два рабочих процесса
  не создадут два запуска для одного пайплайна в одну минуту.
- Созданный запуск сохраняет номер версии графа и событие `schedule`. Для совместимости
  со старыми заданиями имя задания Redis осталось `execute_manual`. Способ запуска
  рабочий процесс читает из сохранённого события и указывает в журнале.
- Блок `source.platform_results` читает результаты всех учеников преподавателя через
  `context.store.find_results` (ADR 0031). В примере недельной сводки начало периода
  отсчитывается от минуты срабатывания. Хранилище читает результаты с этой даты
  на момент выполнения блока.

## Пример

`docs/examples/pipelines/weekly-digest-demo.json` запускается в 18:00 по пятницам и
сохраняет «Сводку за неделю» в кабинете преподавателя. Полный проект сценария 4 в
`scenario-4-analytics.json` также описывает работу с Moodle и рассылку (задачи 26–28).
