# ADR 0033. Получатели email и Telegram

Задача 26. В сценарии еженедельных рекомендаций преподаватель просматривает таблицу
перед рассылкой. Каждый ученик получает сообщение в подключённом канале или в кабинете.

## Решение

- **Два инструмента.** `email.send_email` и `telegram.send_message` запускаются в дочерних
  MCP-процессах по схеме ADR 0028. Оба помечены как действия с внешними последствиями и
  недоступны агенту. Почта использует `smtplib` и TLS с проверкой сертификата. Telegram
  использует `httpx` и фиксированный HTTPS-адрес Bot API. Новых библиотек нет.
- **Контакты.** Преподаватель сохраняет необязательные контакты ученика через API. Почта
  уведомлений хранится отдельно от почты для входа. Для Telegram сохраняется номер личного
  чата, который получатель открыл с ботом. Для демонстрации преподаватель вводит контакты
  вручную с согласия получателя. Самостоятельная привязка остаётся открытым вопросом.
- **Выбор получателя.** Слой сборки берёт `student_id` из подтверждённой строки и ищет
  ученика среди учеников преподавателя запуска. Адрес и номер чата берутся только из его
  карточки и передаются конкретному адаптеру. Для Telegram без входа `recipient`
  используется ученик текущего запуска, как предусмотрено в сценарии 1. Для графов с
  действием без Подтверждения валидатор сохраняет предупреждение ADR 0011. Демонстрационный
  граф отправляет только строки с выхода `approved`.
- **Доступ к сервисам.** Ящик отправителя один на установку платформы. Его параметры
  задаёт администратор через `PLATFORM_SMTP_*`. Токен Telegram свой у преподавателя,
  хранится в `connections` в зашифрованном виде. Дочерняя программа получает только настройки
  своего канала. Ответ API и журнал ошибки не раскрывают секреты и ответ внешнего сервиса.
- **Доставка.** Без контакта блок возвращает `skipped`, и демонстрационный граф переключается
  с Telegram на почту, а затем на кабинет. После ответа внешнего сервиса блок возвращает
  `sent`. Сбой останавливает запуск. Движок не повторяет MCP-действия автоматически:
  после таймаута невозможно уверенно сказать, принял ли сервис сообщение. Если процесс
  прервался на таком узле, при продолжении движок отмечает неизвестный результат и
  останавливает запуск. Состояние не позволяет установить, успел ли начаться вызов.
  Это уточнение правила повторов из ADR 0008. Перед новым запуском нужно проверить, что уже пришло.

## Проверка

Сквозной тест использует настоящие инструменты MCP и заглушки SMTP и Telegram. Он
проверяет паузу, правку текста, доставку в три канала и исключение пропущенной строки.
Порядок ручной проверки с тестовым ящиком и ботом приведён в [инструкции](../deploy.md).
