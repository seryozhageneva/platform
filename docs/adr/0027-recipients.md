# ADR 0027. Получатели «Кабинет», «Банк задач» и «Файл»; показ и скачивание результатов

- **Статус:** принято
- **Дата:** 11.11.2026

Дополняет ADR 0026. Контракт не меняется: блоки пользуются действиями записи из ADR 0026.

## Контекст

В задаче 22 появляются три встроенных блока-получателя: `sink.cabinet`, `sink.task_bank` и
`sink.file`. Им нужно решить три вопроса: как строить ключ записи, кому адресовать результат
и как преподаватель получает готовый файл. Ещё ADR 0026 оставил на эту задачу ограничения
для `save_file` и показ результатов кабинета.

## Решение

**Ключ записи — из входов блока.** Блок берёт отпечаток (SHA-256) от того, что сохраняет:
у «Кабинета» — заголовок, ученик и содержимое; у «Банка задач» — сама задача; у «Файла» —
формат, имя, настройка ответов и содержимое. Повтор после сбоя даёт тот же ключ и не создаёт
дубля. В цикле «для каждого» разные элементы дают разные ключи. Одинаковые элементы в одном
цикле дают одну запись — это намеренно.

**Кому адресован результат** (`sink.cabinet`, настройка `to`):

| Значение | Кому | Откуда ученик |
| --- | --- | --- |
| `teacher` (по умолчанию) | преподавателю | — |
| `student` | ученику запуска | `context.student_id`; нет ученика — ошибка |
| `recipient` | ученику из данных | поле `student_id` значения на входе `recipient`; нет поля — ошибка |

Чужого ученика отклоняет хранилище (ADR 0026).

**Банк задач.** Блок сохраняет задачу как подтверждённую и отдаёт на выход `task` задачу
с номером из банка. Раньше выхода в черновике не было; он нужен, чтобы дальше по пайплайну
ссылаться на задачу банка.

**Файл.** Блок собирает файл сам:

- PDF — библиотекой `fpdf2` со шрифтом DejaVu Sans, который лежит в репозитории
  (`blocks/sink/file/fonts/`, свободная лицензия в `LICENSE_DEJAVU`): так русские буквы
  одинаково выводятся у автора, в CI и на сервере. Библиотеку автор разрешил поставить
  в этой задаче.
- DOCX — `python-docx`, уже стоявшей для чтения документов (задача 19).
- Moodle XML — стандартный формат импорта вопросов Moodle. Задача с кратким ответом
  становится вопросом «Короткий ответ», остальные — «Эссе», которое проверяет преподаватель.
  Текст экранируется как HTML. Звёздочка в эталоне краткого ответа экранируется (`\*`):
  иначе Moodle понимает её как «любые символы» и засчитывает неверные ответы. Из других
  данных, кроме задач, этот формат не собирается.

Настройка `answers` (по умолчанию включена) решает, попадут ли в файл ответы, решения
и критерии. Задача печатается как задача, другие значения — как текст или пары «поле —
значение»; служебные поля (`source`, `id`, `student_id`, `meta`) пропускаются.

**Ограничения для `save_file`** (обещаны в ADR 0026) проверяет блок: только три своих формата,
не больше 10 МиБ — как при загрузке. Имя файла очищается: остаются буквы, цифры, пробел,
точка, дефис и подчёркивание. Управляющие символы, которые нельзя записать в XML и DOCX,
удаляются.

**Как файл доходит до преподавателя.** После сохранения файла блок публикует в кабинет
преподавателя результат `{"file": <ссылка File>}`. Отдельного списка файлов не нужно:
кабинет показывает такой результат ссылкой на скачивание.

**API.**

- `GET /api/v1/results` — результаты преподавателя, новые первыми, не больше 100; у адресованных
  ученику — его номер и имя.
- `GET /api/v1/student/results` — только результаты, адресованные этому ученику, без сведений
  о запуске.
- `GET /api/v1/files/{file_id}/content` — скачать свой файл; только преподаватель-владелец.
  Ответ всегда с `Content-Disposition: attachment` и `X-Content-Type-Options: nosniff`: файл
  не открывается на странице платформы, поэтому файл любого типа не выполнит код от её имени.

## Варианты, которые отклонены

- **Ключ из номера элемента цикла.** Номер в контексте блока не передаётся; добавлять его —
  изменение контракта ради того, что решает отпечаток входов.
- **Отдельный список файлов в кабинете.** Ещё один эндпоинт и экран; результат со ссылкой
  на файл даёт то же.
- **PDF через LibreOffice из DOCX.** Тяжёлая программа в образе сервера ради одной функции.
- **Шрифт из системы.** На сервере и в CI набор шрифтов другой; кириллица могла пропасть.

## Последствия

- Ученик файлы не скачивает: в его кабинете файл показывается только именем. Если понадобится,
  нужно отдельное решение о правах.
- Moodle XML проверен по структуре в тестах; импорт в настоящий Moodle — после появления
  тестового Moodle в задаче 23.
- Если поменять способ построения ключа, повтор старого запуска создаст новую запись (ADR 0026).
