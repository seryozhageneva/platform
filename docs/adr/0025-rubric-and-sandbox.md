# ADR 0025. Проверка по рубрике и запуск кода в HTTP-песочнице

Статус — принято для задачи 21.

## Проверка текста

`check.rubric` получает развёрнутый ответ или текст документа. Критерии берутся из
переданной задачи, а для проверки без задачи — из настройки `rubric`. Рубрика и
условие передаются модели отдельно от ответа. Модель возвращает балл, максимум и
комментарий по фиксированной схеме. Блок отклоняет баллы вне диапазона от нуля до
максимума и пустые комментарии. Полный балл даёт исход `correct`, частичный или
нулевой — `wrong`. В обоих случаях `preliminary: true`.

Проверки в индивидуальном уроке сохраняют оценку вместе с шагом графа. Слой сборки
находит последнюю сдачу того же ответа на ту же задачу в этом запуске. При пересдаче
предыдущая оценка остаётся рядом со своей попыткой. Внешние документы проверяются
через выход блока `verdict` и могут дальше попасть в таблицу подтверждения.

## Проверка кода

В задаче со способом проверки `code` поле `tests` содержит строку с массивом JSON.
В массиве от 1 до 8 объектов со строковыми полями `stdin` и `stdout` до 32 КиБ
каждое в UTF-8.

```json
[
  {"stdin": "2 3\n", "stdout": "5\n"},
  {"stdin": "0 4\n", "stdout": "4\n"}
]
```

Ученик отправляет самостоятельную программу на Python 3.12. Программа читает
`stdin` и печатает результат. Сервис сравнивает вывод с эталоном, игнорируя
переводы строк в конце. Каждый пройденный тест даёт один балл. При полном балле
вердикт верный. Результат проверки тестами окончательный.

HTTP-процесс принимает запрос по существующему контракту и запускает одноразовый
контейнер на каждый тест. В контейнер передаются только код и вход одного теста.
Эталон остаётся в HTTP-процессе. У контейнера отключена сеть, корневая файловая
система доступна для чтения, а временные файлы живут в ограниченной памяти.
Код работает без прав администратора, доступа к Docker и примонтированных каталогов.
Действуют лимиты времени, памяти, CPU, процессов и вывода. У контейнера есть свой
запасной таймер на случай остановки HTTP-процесса. Контейнер удаляется
после каждого теста, в том числе после превышения лимита. Одновременно HTTP-процесс
принимает до двух проверок. Потеря связи с Docker или недоступность HTTP-сервиса
считается ошибкой запуска. Ошибка программы или превышение лимита — непройденный тест.

Сборка платформы подключает HTTP-блок через реестр. Движок вызывает его тем же
способом, что и встроенный блок. Контейнер запускается только из заранее собранного
образа. HTTP-процесс располагается в доверенном окружении с доступом к Docker.
Публичное развёртывание и топология сервиса относятся к задаче 24.

## Локальный запуск

Из корня репозитория, при работающем Docker и установленных зависимостях проекта:

```sh
docker build -t platform-code-runner:local services/sandbox
uv run --no-sync uvicorn services.sandbox.app:app --host 127.0.0.1 --port 8001
```

API и рабочий процесс подключаются к `http://127.0.0.1:8001`. Администратор может
задать другой адрес через переменную окружения `PLATFORM_SANDBOX_URL` для обоих
процессов. В редакторе используются блоки «Проверка: по рубрике с помощью ИИ» и
«Проверка: тесты кода в песочнице». Для урока на Python выбери форму «Код» у блока
приёма ответа и подай его выход на вход `answer` проверки.

Проверка контейнеров и ручной замер модели:

```sh
PLATFORM_TEST_DOCKER=1 uv run --no-sync pytest -q services/sandbox/test_docker.py
uv run --no-sync python -m experiments.rubric_eval
```
