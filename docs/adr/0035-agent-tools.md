# ADR 0035. Агентные инструменты в ИИ-обработке

- **Статус:** принято
- **Дата:** 12.11.2026

Дополняет ADR 0024 (схемы ИИ-обработки), ADR 0028 (MCP-клиент и пометка «только чтение») и
ADR 0032 (недельная сводка). Модели в `backend/core/contracts/` не меняются: поле `tools` в
манифесте, интерфейс `ToolClient` и `context.tools` были в контракте с задачи 02, а
`LLMClient` остаётся одним вызовом модели.

## Контекст

Задача 28: сводка должна сама запросить журнал Moodle. До неё блок ИИ-обработки получал
только то, что ему подали стрелками графа, а `context.tools` никто не заполнял. В сценарии 4
оценки должен был приносить отдельный блок-черновик `source.moodle_grades`, которого не было в
коде.

## Решение

**Инструмент `moodle.get_course_grades(course_id)`.** Новый инструмент MCP-сервера Moodle с
пометкой «только чтение». По каждому заданию курса он отдаёт название, максимум баллов и
выставленные оценки: номер студента в Moodle, оценку и время. Имён нет. Неоценённые работы
(оценка −1 у Moodle) не берутся, у повторной сдачи — последняя попытка. Функции Moodle —
`mod_assign_get_assignments` и `mod_assign_get_grades`; обе уже разрешены тестовому сервису,
`moodle_seed.php` не меняется.

**Агент — цикл на ответах по схеме.** Блок `ai_process.generate` (версия 0.2.0) с непустой
настройкой `tools` на каждом шаге просит модель ответить по схеме одним из двух видов:
`{"action": "call_tool", "tool": …, "arguments": …}` или `{"action": "finish", "result": …}`.
Схема итога — та же, что без агента (ADR 0024). Родной «вызов функций» провайдера не
используется: для этого пришлось бы менять `LLMClient` в контракте, а ответ по схеме уже
работает у любой модели и у `FakeLLM`. LangGraph не подключён: цикл занимает несколько
десятков строк, новая библиотека ему не нужна.

**Границы агента задаёт преподаватель в настройках узла.**

- `tools` — какие инструменты включить узлу; варианты — только инструменты из списка `tools`
  манифеста. Схема шага разрешает только их имена.
- `max_steps` — сколько раз можно вызвать инструмент, по умолчанию 5, от 1 до 10. Когда вызовы
  кончились, схема шага разрешает только итог.
- `course_id` — курс Moodle; обязателен, если включён журнал оценок. Он подставляется поверх
  аргументов модели: агент не заглянет в другой курс, даже если попросит. Это отдельное поле, а
  не общий словарь аргументов: форма редактора не умеет вложенные настройки, а курс
  преподаватель задаёт числом или параметром пайплайна.

Ответ инструмента модель получает в следующем сообщении, длинный — обрезанный до 20 000
знаков. Ошибка инструмента тоже уходит модели текстом: она может поправить аргументы или
обойтись без данных. Без своих инструментов (нет подключения, сервер не отдал инструмент, он
не помечен «только чтение») блок падает до первого вызова модели.

**Инструменты выдаёт слой сборки.** `Assembly` кладёт в `context.tools` объект `AgentTools`
(`backend/triggers/agent_tools.py`) каждому блоку, в манифесте которого есть `tools`, если у
запуска есть преподаватель. `AgentTools` видит только пары «сервер, инструмент» из манифеста
и берёт подключение преподавателя запуска при первом обращении — блоку без включённых
инструментов подключение Moodle не нужно. Пометку «только чтение» по-прежнему проверяет
MCP-клиент при каждом вызове. Движок не меняется.

**Журнал запуска.** Каждый вызов — событие `tool_called` узла: имя инструмента, аргументы и
`ok`. Ответа инструмента в журнале нет: в нём данные учеников.

**Сценарий 4 без черновика.** Узел `get_grades` и черновик `source.moodle_grades.yaml` удалены:
узел «Найти отстающих» сам смотрит журнал. Рабочий пример —
`docs/examples/pipelines/weekly-digest-moodle-demo.json`: недельная сводка с параметром
`course_id`.

## Проверка

- `tests/test_ai_process_generate.py`: агент вызывает журнал и отдаёт итог; курс из настроек
  перекрывает курс модели; чужой инструмент и лишний вызов отвергает схема; ошибка инструмента
  уходит модели; длинный ответ обрезается; без инструментов — ошибка до модели.
- `tests/triggers/test_agent_tools.py`: только инструменты манифеста, подключение
  преподавателя запуска, подключение не берётся до первого обращения, инструмент с
  последствиями отвергается.
- `mcp_servers/moodle/test_server.py`: журнал без имён и без неоценённых, неизвестный курс,
  последняя попытка.
- `tests/e2e/test_weekly_digest_moodle.py`: такт расписания → агент читает журнал → сводка в
  кабинете, событие `tool_called` в журнале. Первый тест — на подделке Moodle, второй — на
  тестовом Moodle с выставленной перед этим оценкой.

## Последствия

- Каждый шаг агента — отдельный вызов модели, и весь разговор отправляется заново: сводка с
  одним вызовом инструмента стоит два вызова модели.
- Каждый вызов инструмента запускает дочернюю программу MCP-сервера (около секунды).
- В журнале Moodle студенты — номера. Связать номер с карточкой ученика платформа пока не
  умеет (ADR 0028), поэтому в сводке студент Moodle называется номером.
- Упавший блок с агентом движок повторяет, как любой автоматический: инструменты только читают,
  повтор безопасен, но снова тратит вызовы модели.
- Модель может ответить не по схеме шага. Слой моделей тогда возвращает ошибку, и блок падает,
  как при неверном итоге без агента.
