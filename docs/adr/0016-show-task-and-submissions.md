# ADR 0016. Блок «Показать задачу», ответ на паузе через API и таблица работ учеников

- **Статус:** принято
- **Дата:** 14.10.2026

Контракт и движок не меняет. Добавляет таблицу `submissions` (отложена в ADR 0007 до задачи 10) и эндпоинт ответа на паузе (отложен в ADR 0013 до задачи 10).

## Контекст

Движок умеет ставить запуск на паузу и принимать ответ человека (`Engine.respond`, ADR 0010). Но блока, который ждёт ученика, не было, ответить запуску через API было нельзя, а таблицы работ учеников не существовало. Задача 10 добавляет все три вещи.

Документы оставили открытыми пять вопросов:

1. кто записывает работу ученика в базу, если у блока хранилище только на чтение (ADR 0014);
2. какой формы таблица работ: ADR 0007 связал её с тем, где хранятся файлы работ;
3. какие ответы блок «Показать задачу» не принимает и что делает с ними;
4. кто отвечает на паузе, пока у ученика нет кабинета (задачи 13 и 14);
5. как API отличает «запуск не ждёт ответа» от «ответ не по форме».

## Варианты

**Кто записывает работу.** (а) Блок — через новый метод хранилища платформы. (б) API — из тела запроса до вызова движка. (в) Слой сборки — по результату блока.

**Номер задачи в работе.** (а) Ссылка на таблицу `tasks`. (б) Строка без ссылки.

**Негодный ответ в блоке.** (а) Блок падает. (б) Блок переспрашивает — снова возвращает «жду человека» с тем же экраном.

## Решение

### Работу записывает слой сборки по результату блока

Вариант (в). Обёртка блока в сборке (`_serviced` в `backend/triggers/assembly.py`, ADR 0015) уже видит каждый вызов. После вызова она смотрит: блок ждал ученика (`kind: interactive`), ему пришёл ответ человека, и он вернул «готово». Тогда каждый выход типа `Answer` записывается в `submissions`.

Вариант (а) — изменение контракта: хранилище платформы только на чтение (ADR 0014). Вариант (б) записал бы и ответы, которые блок не принял: переспрос и просьбу подсказки.

Без преподавателя в запуске работа не записывается: её владельцем был бы никто. Так же сборка не выдаёт хранилище платформы.

Если запись не удалась, для движка это падение блока, и текст ошибки он пишет в состояние запуска и журнал. Текст ошибки базы цитирует запрос вместе с ответом ученика, поэтому сборка заменяет его на «не удалось записать работу ученика» и вид ошибки — так же движок поступает с ошибками хранилища.

### Таблица `submissions`

Одна строка — одна работа: принятый ответ в уроке или (с задачи 23) работа, сданная в Moodle.

| Столбец | Что хранит |
| --- | --- |
| `owner_id` | преподаватель-владелец; читает работы только он (ADR 0007) |
| `student_id` | ученик; пусто у пробного запуска преподавателя — у запуска «вручную» ученика нет |
| `run_id`, `node_id` | запуск и узел, в котором дан ответ |
| `task_id` | номер задачи строкой (вариант б): у задания Moodle номер не из нашей базы |
| `source` | `platform` или `moodle` |
| `form`, `text`, `file` | форма ответа, текст и ссылка на файл (`File` из контракта) |
| `score`, `max_score`, `comment`, `verdict_status` | оценка и вердикт; пусты, пока работу не проверили |

Файл работы в базе не лежит — только ссылка на него. Если файла нет, в столбце пустое значение базы, а не JSON `null`: так работает поиск «работы без файла». Где лежат сами файлы, решат задачи 14, 19 и 31; форма таблицы от этого не зависит, поэтому её можно создать уже сейчас.

### Блок «Показать задачу и принять ответ»

Первый вызов строит экран «форма ответа»: номер задачи, условие, разрешённые формы ответа, подсказку и «можно ли просить подсказку». Ответ и эталонное решение в экран не попадают. Подсказка показывается, только если она к этой же задаче: после смены задачи подсказка к прошлой ещё лежит в состоянии запуска.

Второй вызов: просьба подсказки — исход `hint_requested`; ответ-фото — `photo`; остальное — `answer` с выходом `answer`.

**Переспрос** (вариант б). Блок не принимает ответ и снова показывает тот же экран, если ответ к другой задаче (`other_task` — например, из старой вкладки), в неразрешённой форме (`form_not_allowed`), пустой (`empty_answer`), с нулевым символом, который база не записывает (`bad_characters`, ADR 0007), или просят подсказку, когда она выключена (`hints_off`). Причина пишется в журнал событием `response_refused`. Это право блока, записанное в ADR 0010: «блок может спросить ещё раз».

В журнал идут `task_shown`, `answer_received`, `hint_requested` и `response_refused` — с номером задачи и формой ответа, но без текста ответа (ADR 0010).

### Ответ через API

`POST /api/v1/runs/{run_id}/responses` с телом `{"node_id": ..., "response": {...}}`. Форма `response` своя у каждого экрана. Ответ сервера — состояние запуска, как у запроса на запуск (ADR 0013): закончился, снова ждёт или остановился с ошибкой.

| Код | Когда |
| --- | --- |
| 200 | ответ передан блоку; запуск пошёл дальше или блок переспросил |
| 404 | запуска нет или он чужой |
| 409 | запуск не ждёт ответа на этом узле: уже ответили, он закончился или ждёт на другом |
| 422 | ответ не подходит экрану; состояние запуска не меняется |

Общая часть — функция `answer_run` в `backend/triggers/responses.py`: она продолжает запуск на той версии пайплайна, с которой он стартовал. Ею воспользуется кабинет ученика (задача 14).

Пока у ученика нет входа, на паузе своего запуска отвечает преподаватель — по тому же заголовку, что и для остальных запросов (ADR 0013).

В `GET /runs/{id}` у ожидания появились данные экрана (`data`): без них отвечающий не видит, на что отвечает. Значений портов по-прежнему нет. У формы ответа в данных экрана нет ответа и решения — так устроен экран в контракте.

## Последствия

- Критерий «запуск встаёт на паузу и продолжается после ответа» закрыт тестом `tests/api/test_responses_api.py` на настоящих блоках и ручной проверкой `experiments/api_check.py`.
- Переспрос молчаливый: ученик снова видит тот же экран, но не видит почему. Сообщение об ошибке требует поля в данных экрана — это изменение контракта, отдельная задача с ADR, если понадобится в задаче 14.
- Работа записывается до того, как движок сохранит шаг. Если сохранение шага сорвётся, движок откатит шаг, человек ответит ещё раз — и в таблице будут две записи одного ответа.
- Два одновременных ответа на одну паузу оба пройдут проверку «запуск ждёт» и оба продвинут запуск. Защита — вместе с фоновой очередью (задача 18a).
- Номер задачи в работе ни на что не ссылается: удалённая задача банка не удалит работы по ней, а опечатка в номере не будет замечена базой.
- Оценку и вердикт в работу пока никто не пишет: это сделают задачи проверки (11, 21) и Подтверждение (18).
- Ответ, распознанный с фото (`transform.photo_to_latex`, задача 31), работой не записывается — записывается само фото. Нужна ли запись распознанного текста, решится в задаче 31.
