# ADR 0036. Облако (Яндекс Диск) как Источник

- **Статус:** принято
- **Дата:** 12.11.2026

Дополняет ADR 0028 (MCP-сервер дочерней программой, таблица подключений) и ADR 0033 (вид
подключения с постоянным адресом, как у Telegram). Модели в `backend/core/contracts/` не
меняются. В `docs/contract.md`, раздел 2, уточнено только, что поле ответа MCP-инструмента со
значением `null` при исходе, отличном от `ok`, значит «этого выхода нет».

## Контекст

Задача 29: лекция для сценария 3 должна браться из облака, а не только из загруженного файла.
В `docs/vision.md` облако — Яндекс Диск, и это MCP-адаптер с подключением преподавателя, как
Moodle. Папка `mcp_servers/cloud/` была пустой с задачи 01.

## Решение

**MCP-сервер `mcp_servers/cloud`, один инструмент `get_file(path)`.** Пометка «только
чтение». Путь — от корня Диска: `/Лекции/лекция.pdf` или `disk:/Лекции/лекция.pdf`. Сервер
спрашивает у REST API Диска описание ресурса, затем ссылку на скачивание и скачивает файл.
Ответ — `{file, outcome}`: `ok` с файлом в base64 или `missing`, если по пути ничего нет. Папка
вместо файла, неверный токен, отказ Диска — понятная ошибка без токена и без ответа Диска.
Вид файла (`document` для PDF и DOCX, `image`, `other`) сервер определяет по расширению. В
`meta` файла — `cloud_path`, откуда он взят.

**Токен идёт только на API Диска.** Адрес API постоянный — `https://cloud-api.yandex.net`.
Ссылка на скачивание уже подписана Диском, по ней файл берётся без токена. Сервер скачивает
только по HTTPS с серверов `yandex.ru` и `yandex.net` и сам разбирает переадресации: каждая
проверяется так же, не больше пяти. Ссылку на другой сайт он не открывает. Предел — 10 МиБ,
как у загрузки файлов платформы: проверяется и по описанию, и при скачивании.

**Подключение `cloud`, миграция 0013.** Вид подключения совпадает с именем сервера (ADR 0028).
Адрес, как у Telegram, вписывается сам; другой адрес отклоняется. Токен OAuth проверяется по
формату (буквы, цифры, `_`, `-`, `.`, от 16 знаков), шифруется и не возвращается. Дочерняя
программа получает только `CLOUD_TOKEN`. Токену нужен только доступ на чтение Диска.

**Блок `source.cloud_file`.** Настройка `path`, выход `File`, исходы `ok` и `missing`, без
последствий. Файл сохраняется в файлы преподавателя тем же путём, что работы из Moodle
(ADR 0028): повтор блока не создаёт копий. Пример — `cloud-lecture-demo.json`: сценарий 3, в
котором `source.file` заменён на `source.cloud_file`.

**Пустой выход.** SDK MCP отдаёт поле `file: null` при исходе `missing`. Слой сборки теперь
пропускает поля со значением `null` при исходе, отличном от `ok`: выхода просто нет. При
`ok` пустой выход по-прежнему роняет блок понятной ошибкой: значит, сервер ответил неверно.

## Отвергнуто

- **Публичные ссылки Диска без токена.** Проще для преподавателя, но лекция становится
  доступна всем, у кого есть ссылка. Можно добавить отдельным инструментом позже.
- **WebDAV Яндекс Диска.** Нужен пароль приложения, а не токен с одним правом на чтение.
- **Блок на Python без MCP.** В `docs/vision.md` облако — MCP-адаптер. Так второе облако
  добавляется новым сервером без изменений в платформе, это и замеряется в главе «Оценка».

## Проверка

- `mcp_servers/cloud/test_server.py` — на подделке Диска (`mcp_servers/cloud/testing.py`):
  скачивание, обе формы пути, `missing`, папка, неверный токен, плохой путь до сети, токен
  только на API, чужой сайт и переадресация внутри Яндекса, предел 10 МиБ, отказ Диска.
- `tests/api/test_connections_api.py` — подключение `cloud`: адрес постоянный, токен не
  возвращается, неверный формат отклоняется.
- `tests/triggers/test_mcp_blocks.py` — сервер запускается дочерней программой только с
  `CLOUD_TOKEN`, инструмент помечен «только чтение».
- `tests/e2e/test_scenario_3_cloud.py` — подключение через API, запуск сценария 3 из облака,
  лекция в файлах преподавателя, конспект в кабинете; при `missing` модель не вызывается.
- `experiments/cloud_check.py` — ручная проверка на настоящем Диске; идёт в сеть, токен
  спрашивает сам.

## Последствия

- Облако — только чтение одного файла. Папки, запись на Диск и выбор файла мышкой в браузере
  в задачу не входят.
- Формы подключения в браузере всё ещё нет: токен сохраняется через API (открытый вопрос 31).
- Отладочный токен Яндекса выдаётся на год; когда истечёт, блок скажет, что Диск не принял
  токен, и подключение нужно сохранить заново.
