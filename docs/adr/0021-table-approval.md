# ADR 0021. Табличное подтверждение преподавателем

- **Статус:** принято
- **Дата:** 10.11.2026

## Контекст

В задаче 18 преподаватель просматривает результаты одной таблицей, правит разрешённые поля и решает, какие строки передать дальше. Движок уже сохраняет экран паузы в состоянии запуска. Для истории решений нужна отдельная таблица `approvals` (ADR 0007).

## Решение

- Встроенный блок `approval.review_table` использует существующий экран `review_table`. В настройке `editable_fields` через запятую перечисляются текстовые поля. Точка отделяет вложенное поле, например `task.statement`. По умолчанию все поля доступны для просмотра. Ключи `id` и `*_id` остаются доступны только для просмотра. Встроенный блок сверяет ответ с сохранённым экраном и требует по одному решению на каждую строку. Движок проверяет итог по фактическому типу порта, прежде чем записать решение. Другие блоки используют общую форму ответа экрана и при необходимости добавляют свои проверки. Блок передаёт оставленные записи в исходном порядке, сохраняя их форму. Пустой вход или отклонение всех строк дают исход `rejected` и пустой выход.
- Хранилище создаёт запись подтверждения в той же транзакции, что и паузу запуска. В записи остаются снимок экрана, преподаватель, узел, время открытия, решение, правки и время ответа. Ответ сохраняется вместе с состоянием после шага, до исполнения следующего узла. Журнал показывает только исход и числа строк. Миграция создаёт записи для уже сохранённых табличных пауз.
- API читает экран и идентификатор подтверждения одним запросом. При ответе он проверяет этот идентификатор под блокировкой запуска. Назначенный урок использует общую блокировку для действий ученика и преподавателя. Новый проход через тот же узел получает новый идентификатор. Ученик видит только статус ожидания, а преподаватель открывает таблицу в своём кабинете.

## Последствия

Процесс можно продолжить после перезапуска сервера. Повторный или устаревший ответ получает конфликт. Версия пайплайна и формы обмена с блоками остаются прежними.
