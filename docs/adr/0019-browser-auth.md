# ADR 0019. Вход в браузере и личные ссылки учеников

## Решение

Преподаватель входит по почте и паролю. Учётные записи заводит администратор командой
`backend.api.create_teacher`. Пароль хранится в виде хэша Argon2id. Для записи, созданной
до задачи 13 без пароля, администратор явно задаёт первый пароль.

При входе сервер создаёт случайный токен и выдаёт его браузеру в cookie с `HttpOnly`,
`SameSite=Lax` и `Secure` при HTTPS. В PostgreSQL хранится только хэш токена и срок
сеанса. Сеанс действует до 8 часов. Выход удаляет сеанс из базы. Сервер принимает запросы
на изменение состояния с того же адреса, на котором открыта платформа. В разработке
Vite пересылает запросы `/api` серверу. При развёртывании браузерная часть и API также
будут открываться с одного адреса по HTTPS.

Преподаватель создаёт учеников по псевдонимам и выдаёт ссылки с экрана «Ученики». Ссылка
действует 30 дней и допускает повторный вход. Браузер берёт токен из части адреса после
`#`, очищает адресную строку и передаёт токен в теле запроса. База хранит хэш ссылки и её
срок. Сеанс ученика заканчивается не позднее срока ссылки.

Тот, у кого есть ссылка, может войти как ученик. Если ссылку переслали, преподаватель
вручную отзывает её или выпускает новую. Операция закрывает все текущие сеансы ученика
в той же транзакции. Вход и управление ссылкой блокируют одну строку ученика, поэтому
параллельный вход не сможет оставить действующий сеанс после отзыва.

Запросы к данным преподавателя используют его учётную запись из сеанса. Чужая запись
даёт тот же отказ `404`, что и отсутствующая. При смене сеанса вкладки перечитывают
текущую учётную запись. Если запрос из прежнего кабинета успел уйти, сервер сверяет
указанный кабинетом ID с учётной записью из cookie и возвращает `409` при расхождении.
Ученику доступны его вход, проверка
сеанса и выход. Урок и запуск от имени ученика появятся в задаче 14.

## Локальный запуск

Из корня проекта после установки зависимостей и запуска PostgreSQL:

```sh
uv run alembic upgrade head
uv run python -m backend.api.create_teacher a@example.test --name 'Демо А'
uv run python -m backend.api.create_teacher b@example.test --name 'Демо Б'
LLM_PROVIDER=fake uv run python -m backend.api
```

Для старой демонстрационной записи без пароля используй
`uv run python -m backend.api.create_teacher demo.teacher@example.test --set-initial-password`.
Пароль вводится скрыто. Для ручной проверки `experiments.api_check` нужна именно запись
`demo.teacher@example.test`.

В отдельном терминале запусти `pnpm --dir frontend dev` и открой адрес из вывода Vite.
Для проверки ученической ссылки используй отдельный браузерный профиль: у каждого профиля
свой сеанс. После отзыва обнови страницу в профиле ученика.

После изменения API обнови типы командой `pnpm --dir frontend api:generate`. Для проверки
соответствия клиентских типов схеме служит `pnpm --dir frontend api:check`.
