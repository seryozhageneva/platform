# ADR 0020. Назначение и прохождение урока

## Решение

Преподаватель назначает свой пайплайн своему ученику через `POST /api/v1/assignments`.
Сервер проверяет триггер `student`, доступность блоков, настройки с подставленными
параметрами и совместимость экранов с кабинетом. Ученик видит свои назначения
после входа по личной ссылке. При первом открытии сервер снова
проверяет актуальную версию пайплайна и записывает её вместе с назначением в строку
запуска. При следующих открытиях используется эта же версия. Ограничение в PostgreSQL
допускает один запуск на ученика и назначение.

Открытие и ответ берут одну блокировку на назначение. Для блокировок выделен
отдельный пул соединений, поэтому они не занимают соединения, нужные движку.
Если параллельный запрос держит блокировку, сервер возвращает `409`. Если
свободного соединения для блокировки нет, сервер предлагает повторить запрос (`503`).
Ответ включает версию показанного экрана, полученную из ревизии строки запуска
в PostgreSQL. Если экран успел измениться,
сервер возвращает `409`, а кабинет перечитывает урок. Это работает и когда разные
задачи показывает один и тот же блок. Принятая работа и состояние после шага
сохраняются в одной транзакции. При прерывании до её завершения ответ можно
отправить снова без дубликата работы. Для запуска, прерванного в состоянии
`running`, повторное открытие вызывает продолжение с сохранённого шага.

Ученик получает статус урока и данные текущей ученической формы ответа. Эталон,
внутренние выходы блоков, журнал и данные паузы преподавателя остаются на сервере.
Кабинет принимает текст и формулы с клавиатуры. Преподаватель по-прежнему может
отвечать на паузе ручного запуска.

## Локальная проверка

Из корня проекта при запущенном PostgreSQL выполни:

```sh
uv run --locked --no-sync alembic upgrade head
uv run --locked --no-sync python -m backend.api.create_teacher lesson.demo@example.test --name 'Демо урока'
uv run --locked --no-sync python -m experiments.student_lesson_demo
```

Если демонстрационный преподаватель уже есть, используй его действующий пароль.
В другом терминале выполни `pnpm --dir frontend dev`. Войди преподавателем, создай
ученика с выдуманным псевдонимом и скопируй личную ссылку. Открой `http://127.0.0.1:8000/docs` в том же профиле. Cookie привязана к имени хоста, поэтому на обоих портах используй
`127.0.0.1`.

1. Через `POST /api/v1/pipelines` сохрани [пример урока](../examples/pipelines/student-lesson-demo.json).
2. Через `POST /api/v1/tasks` добавь задачу с предметом `Математика`, темой
   `Дроби`, сложностью `1`, условием `Сократите дробь 4/8.`, способом
   проверки `short_answer` и эталоном `1/2`.
3. Через `POST /api/v1/assignments` передай `student_id`, `pipeline_id` и
   `params` со значениями `{"topic": "Дроби", "n_tasks": 1}`. ID ученика
   можно получить через `GET /api/v1/students`.
4. В отдельном профиле открой личную ссылку, выбери урок и попроси подсказку.
   Обнови страницу и снова открой урок. Убедись, что подсказка видна. Выбери
   форму «Формула» и отправь `2/4`. Должно появиться «Урок завершён».
   Сервер демонстрации рассчитан на один запрос подсказки. Для повтора создай
   новое назначение и перезапусти сервер демонстрации.
