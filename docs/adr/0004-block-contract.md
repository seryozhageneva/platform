# ADR 0004. Контракт блока: порты, манифест и run()

- **Статус:** принято
- **Дата:** 12.10.2026

## Контекст

Контракт — главный инженерный результат работы: по нему стыкуются движок, блоки, адаптеры и редактор. В рабочей записке он описан в общих чертах, а два места оставлены открытыми (`docs/open-questions.md`, вопросы 10 и 21).

**Вопрос 21.** По каталогу блоков сценарии не собираются: Триггер выдаёт `Event`, а Источник ждёт `Query`; Источник выдаёт `Data`, а «показать задачу» ждёт `Task`; Преобразование выдаёт `Text`, а ИИ-обработка ждёт `Data`.

**Вопрос 10.** Не определено, как блок сообщает движку, что ждёт человека, и какие порты у тьютора.

Проверка решения — четыре сценария из записки: они должны записаться в формате контракта и пройти проверку стыковки портов.

## Варианты

**Совместимость типов.** (а) Только точное совпадение — тогда каждому блоку, которому всё равно, что принимать (Получатель «кабинет», ИИ-обработка), нужна своя копия на каждый тип. (б) Таблица «какой тип во что превращается» — гибко, но её пришлось бы править при каждом новом виде данных. (в) Точное совпадение плюс один общий случай: вход `Data` без уточнения принимает любое значение.

**Тип выхода универсального блока.** ИИ-обработка в одном узле выдаёт конспект, в другом — список задач. (а) Отдельный блок на каждый результат — пять почти одинаковых блоков. (б) Выход «неизвестно что» — тогда проверка стыковки после такого блока ничего не ловит. (в) Тип выхода вычисляется для узла: из настройки или из того, что подано на вход.

**Ожидание человека.** (а) Блок «висит», пока человек не ответит, — не переживает перезапуск сервера и не работает для HTTP-сервиса. (б) Два метода: `start()` и `resume()` — интерфейс перестаёт быть одним для трёх способов запуска. (в) Один `run()`, который вызывается дважды.

## Решение

**Тип данных** — вид (один из восьми), уточнение (только у `Data`) и «список или один». Каждый блок объявляет точный тип: «банк задач» выдаёт `Task`, а не общее `Data`. Выход стыкуется со входом, если типы совпадают целиком либо вход объявлен как `Data` без уточнения — «принимаю любое» (вариант в).

**Тип `Query` убран.** Запрос Источника — это его настройки с подстановкой параметров пайплайна. Триггер с Источником типами не стыкуется вообще: что выполнять дальше, решают переходы, а не привязки данных (ADR 0005).

**Вычисляемый тип выхода** (вариант в): `same_as` — повторяет тип входа, `from_config` — записан в настройке узла.

**Ожидание человека** (вариант в). `run()` возвращает одно из двух: «готово» (выходы, исход, события) или «жду человека» (экран и данные для него). Движок ставит паузу и позже вызывает тот же `run()` с теми же входами, положив в `context.human_response` ответ человека, а в `context.shown` — данные экрана, которые блок сам попросил показать. Блок ничего не помнит между вызовами.

**Экраны.** Четыре готовых экрана платформы: форма ответа, подтверждение распознанного, таблица на подтверждение, документ на подтверждение. У каждого своя форма данных и своя форма ответа. В данных формы ответа есть только условие задачи — эталонного решения там нет по самой форме.

**Тьютор** — блок `auto`: входы «задача», «ответ», «вердикт», «прошлая подсказка» (три последних необязательные), выход «подсказка», исходы `hint` и `give_up`.

Полное описание — `docs/contract.md`, разделы 1–3.

## Последствия

- Все четыре сценария собраны из 22 блоков и проходят проверку стыковки (`tests/contracts/test_scenarios.py`).
- Новый вид данных автор блока добавляет сам — уточнением у `Data`; контракт при этом не меняется. Новый вид верхнего уровня или новый экран — изменение контракта, отдельная задача с ADR.
- Уточнения сравниваются по имени, а не по содержимому. Два автора могут назвать разные данные одинаково — за этим должен следить реестр блоков (задача 06).
- Значение на порту — последнее записанное. В цикле оно может остаться от прошлой задачи, поэтому у `Answer`, `Verdict` и `Hint` есть `task_id`, и блок сам сверяет его с текущей задачей. Это цена простого движка.
- Модели строгие: незнакомое поле в манифесте — ошибка. Опечатки видны сразу, зато добавление поля в контракт требует обновить все манифесты, где оно обязательно.
- Блок, который ждёт человека, вызывается дважды с одними и теми же входами. Дорогую работу первого вызова (распознавание фото) он не повторяет: результат лежит в данных экрана и возвращается ему в `context.shown`. Поэтому ученик подтверждает ровно тот текст, который дальше и используется.
