## Кто я и что мы делаем

Я студент 4 курса (программная инженерия), пишу ВКР «Платформа для построения персонализированных учебных пайплайнов на основе ИИ-агентов». Весь код пишешь ты, Claude Code. Я не программист: читаю, одобряю, задаю вопросы и учусь по ходу. Срок — до 1 января, но если не успеем, ничего страшного.

Полное описание проекта лежит в `docs/vision.md`, план из 34 задач — в `docs/roadmap.md`. Прочитай оба файла перед началом.

Работаю на macOS (Apple Silicon), в приложении Claude Desktop, вкладка Code.

## Как со мной работать в этом файле

1. **Идём строго по этапам.** Выполнил этап — остановись, коротко отчитайся (что сделано, что проверил, что мне сделать руками) и жди моего «дальше».
2. **Объясняй простыми словами.** Каждую команду, которую предлагаешь выполнить, поясняй одной фразой: что она делает и зачем.
3. **Новые термины записывай в `docs/glossary.md`** (создай его на этапе 3) — объяснение «как школьнику» и пример из нашего проекта.
4. **Ничего не устанавливай и не удаляй без моего подтверждения.** Если нужно ввести пароль, войти в аккаунт или вставить секретный ключ — скажи, что сделать, и я сделаю это сам.
5. **Не пиши код самой платформы.** Этот файл только про подготовку. Код начнётся с задачи 01 из `docs/roadmap.md`, и её мы запустим отдельно.
6. Если что-то пошло не так — не обходи проблему, а объясни, что случилось, и предложи варианты.

3. Для отсутствующих предложи команды установки через Homebrew. Docker — через OrbStack (`brew install --cask orbstack`), после установки мне нужно один раз открыть OrbStack.

## Этап 4. CLAUDE.md

Цель: короткая памятка, которую ты будешь читать в начале каждой сессии.

1. Запусти `/init` или создай `CLAUDE.md` вручную — затем перепиши его коротко, **не длиннее одной страницы**:
   - одна фраза о проекте и ссылки на `docs/vision.md`, `docs/roadmap.md`, `docs/glossary.md`;
   - стек (Python 3.12 + FastAPI + PostgreSQL + Redis; React + TypeScript + Vite + React Flow; Docker Compose; LangGraph внутри блоков; MCP для адаптеров);
   - структура папок из `docs/vision.md` (пока её нет — отметь, что появится в задаче 01);
   - команды запуска и тестов (пока заглушка, заполним в задаче 01);
   - правила работы (ниже).
2. Правила, которые обязательно должны быть в `CLAUDE.md`:
   1. Одна задача — одна ветка `task/NN-название` — один pull request.
   2. Контракты в `backend/core/contracts/` не меняются без отдельной задачи и ADR.
   3. Задача заканчивается зелёными тестами; показывай вывод тестов, а не «всё работает».
   4. Модули связаны только через контракты: блок не импортирует движок, движок не импортирует блоки.
   5. В тестах — фейковая LLM; реальные модели только в ручных прогонах.
   6. После задачи отметь её в `docs/roadmap.md`; если принималось архитектурное решение — добавь ADR в `docs/adr/`.
   7. Новые термины — в `docs/glossary.md`.
   8. Автор учится: объясняй решения простыми словами, в конце задачи — 3 пункта «что важно понимать про эту задачу на защите».
   9. При сжатии контекста всегда сохраняй: номер текущей задачи, список изменённых файлов, команды тестов.
3. Покажи мне итоговый `CLAUDE.md`, после моего одобрения — закоммить.

**Готово, когда:** `/context` показывает, что `CLAUDE.md` загружен.

## Этап 5. Настройка Claude Code в проекте

Цель: инструменты, которые сделают каждую следующую задачу однотипной и надёжной. После каждого пункта объясняй, что это и как я буду этим пользоваться.

1. **Скилл `/next-task`** — `.claude/skills/next-task/SKILL.md`, вызывается только вручную (`disable-model-invocation: true`). Он должен: прочитать `docs/roadmap.md`, взять первую невыполненную задачу или задачу с номером из `$ARGUMENTS`, прочитать нужные части `docs/vision.md` и `docs/contract.md` (когда появится), создать ветку `task/NN-название` и составить план: какие файлы меняются, какие тесты пишутся, как проверить «готово, когда», что не входит в задачу, какие допущения сделаны. В конце плана — пересказ простыми словами. Ничего не реализовывать до одобрения плана.
2. **Субагент `reviewer`** — `.claude/agents/reviewer.md`, инструменты Read, Grep, Glob, Bash. Проверяет изменения текущей ветки против «готово, когда» из `docs/roadmap.md` и правил `CLAUDE.md`: контракты не нарушены, модули не импортируют друг друга напрямую, тесты есть и проходят, ничего лишнего вне задачи не изменено. Сообщает только о проблемах, влияющих на корректность и требования, без стилистики.
3. **Хуки форматирования** в `.claude/settings.json`: после правки `.py`-файла — `ruff format` и `ruff check --fix`; после правки файлов в `frontend/` — prettier и eslint. Хук должен молча пропускаться, если инструмента ещё нет (он появится в задаче 01).
4. **Разрешения** в `.claude/settings.json`: разрешить без вопросов безопасные команды (`git status`, `git diff`, `git log`, `pytest`, `ruff`, `uv run`, `pnpm test`, `pnpm lint`, `docker compose ps`, `docker compose logs`); запретить чтение `.env` и любые `rm -rf`. Объясни мне каждое правило.
5. Закоммить.

**Готово, когда:** `/next-task` виден в списке команд, субагент `reviewer` виден в `/agents` (или в меню приложения).
