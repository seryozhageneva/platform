## Решения (с причинами)

- **`AGENTS.md` — главный файл правил, `CLAUDE.md` только подключает его.** Codex читает `AGENTS.md`, Claude Code — `CLAUDE.md`; одна копия правил не расходится.
- **Список задач — только `docs/roadmap.md`.** Он уже есть и по нему работает `next-task`; отдельный TASKS.md дублировал бы его.
- **Пуш и pull request — только по команде автора, сливает только автор.** Так решил автор.
- **Помощники агентов хранятся в двух копиях** (`.claude/…` и `.codex/…`, `.agents/…`) и правятся вместе. У агентов разные форматы настроек.
- **`.codex/hooks.json` и `.codex/hooks/` в `.gitignore`.** В `hooks.json` полный путь с именем пользователя Mac — работает только на компьютере автора; `format.sh` — точная копия `.claude/hooks/format.sh`.
- **Инфраструктура передачи — в отдельной ветке `docs/agent-handoff`, а не в `task/18a`.** Иначе она попала бы в pull request задачи 18a (правило «одна задача — одна ветка»).
- **В `AGENTS.md` взяты актуальные строки из `CLAUDE.md`** (старый `AGENTS.md` был копией до задачи 13) и дописаны команды рабочего процесса очереди и проверок фронтенда из CI.

## Известные проблемы и подводные камни

- Пока `docs/agent-handoff` не слита в `main`, в ветке `task/18a-background-queue` нет `AGENTS.md` и `HANDOFF.md`: переключение на неё «прячет» эти файлы.
- Для ручных запусков нужны два процесса: `uv run python -m backend.api` и `uv run arq backend.triggers.worker.WorkerSettings`. Если в журнале запуска только `run_queued` — рабочий процесс не запущен или не видит Redis (ADR 0022).
- Автоматического восстановления зависших запусков в 18a нет (ADR 0022).
- На origin остались ветки уже слитых задач 12–17. Удалять — только с разрешения автора.
