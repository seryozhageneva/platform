## Решения (с причинами)

- **Один контейнер на тест Python.** Контейнер видит только текущий вход и код, а сравнение с эталоном делает HTTP-процесс. Локальная схема и формат тестов описаны в ADR 0025.
- **Оценка сохраняется у попытки.** Слой сборки записывает вердикт и состояние шага одной транзакцией. Оценка по рубрике остаётся предварительной.
- **Готовые схемы для ИИ-обработки.** Преподаватель выбирает схему по имени. Это позволяет проверить ответ по схеме уже в задаче 20. Общую защиту проверки схем портов и настроек нужно сделать отдельной задачей до ввода произвольных схем (открытый вопрос 29, ADR 0024).
- **Загрузка через API, выбор по номеру.** Автор выбрал этот вариант для задачи 19. API читает тело по частям, чтобы остановиться при превышении лимита, и проверяет, что указанный ученик принадлежит преподавателю.
- **`AGENTS.md` — главный файл правил, `CLAUDE.md` только подключает его.** Codex читает `AGENTS.md`, Claude Code — `CLAUDE.md`; одна копия правил не расходится.
- **Список задач — только `docs/roadmap.md`.** Он уже есть и по нему работает `next-task`; отдельный TASKS.md дублировал бы его.
- **Пуш, pull request и слияние — только по команде автора.** Так решил автор.
- **Участие Codex.** По договорённости с автором добавлять «Реализовано при участии OpenAI Codex» в описание основного коммита или pull request, если Codex вносил изменения в задачу.
- **Помощники агентов хранятся в двух копиях** (`.claude/…` и `.codex/…`, `.agents/…`) и правятся вместе. У агентов разные форматы настроек.
- **`.codex/hooks.json` и `.codex/hooks/` в `.gitignore`.** В `hooks.json` полный путь с именем пользователя Mac — работает только на компьютере автора; `format.sh` — точная копия `.claude/hooks/format.sh`.
- **В `main` не коммитим напрямую, даже `HANDOFF.md`.** Всё идёт через ветку и pull request; обновление `HANDOFF.md` после слияния едет с первым коммитом следующей задачи.
- **Нестабильный тест чиним, а не перезапускаем CI** (выбор автора). Тест «при потере ответа…» теперь ждёт вызов через `vi.waitFor`.

## Известные проблемы и подводные камни

- До сквозного прогона сценария 3 в задаче 24 передавать узлу «Решить независимо» только условие и идентификатор задачи. Сейчас в его входе есть эталон и решение, поэтому совпадение с эталоном само по себе не подтверждает независимость проверки (ADR 0024).
- Задача 19 извлекает текст из текстового слоя PDF и тела DOCX. Для скана без текстового слоя в журнале появляется сообщение об отсутствии текста.
- После правки таблиц нужно добавить новую таблицу и в список `TABLES` в `tests/models/test_migrations.py`.

- Тесты фронтенда, проверяющие вызовы API после `setState`, могут «плавать» на медленной машине CI: повторный запрос делает эффект React уже после отрисовки. Такие проверки оборачивать в `vi.waitFor`.
- Для ручных запусков нужны два процесса: `uv run python -m backend.api` и `uv run arq backend.triggers.worker.WorkerSettings`. Если в журнале запуска только `run_queued` — рабочий процесс не запущен или не видит Redis (ADR 0022).
- Автоматического восстановления зависших запусков нет (ADR 0022).
- На origin остались ветки уже слитых задач 12–17, 18a, 18b, 19 и 20. Удалять — только с разрешения автора.

- **Хук.** Локальные `.codex/hooks.json` и исполняемый `.codex/hooks/format.sh` на месте и игнорируются Git. В пользовательском конфиге есть запись доверия для этого хука. По [документации Codex](https://learn.chatgpt.com/docs/hooks) `Edit|Write` подходит для `apply_patch`. Автоматический вызов в этой сессии отдельно не подтверждён.
- **Скилл.** Codex прочитал и применил `.agents/skills/next-task/SKILL.md` при планировании задачи 19 по просьбе автора. Поддержка `disable-model-invocation`, `argument-hint` и автоматической подстановки `$ARGUMENTS` в этой сессии не подтверждена. Для запрета автоматического вызова [документация Codex](https://learn.chatgpt.com/docs/build-skills) описывает `policy.allow_implicit_invocation: false` в `agents/openai.yaml` внутри скилла.
