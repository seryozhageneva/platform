## Решения (с причинами)

- 11.11.2026: пилот на настоящих учениках убран из карты (задача 25 удалена, задачи 26–34
  перенумерованы в 25–33, ссылки в документах и коде поправлены; задач 38). Причина: автор решит позже, проводить ли его и как. Правила
  про данные учеников в `AGENTS.md` оставлены — они нужны, если пилот всё же будет.

- **Задача 23 не разбивается** (выбор автора), хотя по объёму больше дня.
- **Тестовый Moodle — отдельный файл Compose, сервер MCP — дочерняя программа на вызов**
  (ADR 0028): токены разных преподавателей не встречаются в одном процессе.
- **Установка для задачи 23 разрешена** при одобрении плана: `mcp`, `cryptography`, Docker-образы
  Moodle и его базы.
- **Передача файлов через MCP описывается внутри задачи 23** — в `docs/contract.md` и ADR 0028,
  без правки моделей `backend/core/contracts/`. Отдельная задача по контракту не нужна.

- **Получатели строят ключ из входов, файл доходит до преподавателя через кабинет** (ADR 0027). Номера элемента цикла в контексте нет, а отдельный список файлов — лишний экран и эндпоинт.
- **PDF — fpdf2 со шрифтом в репозитории** (выбор автора). Системные шрифты на сервере и в CI другие, кириллица могла пропасть.
- **Запись блоков — через `context.store` с ключом результата** (ADR 0026). Слой сборки не должен понимать выходы каждого получателя (правило 4), а ключ защищает от двойной записи при повторе блока.

- **Один контейнер на тест Python.** Контейнер видит только текущий вход и код, а сравнение с эталоном делает HTTP-процесс. Локальная схема и формат тестов описаны в ADR 0025.
- **Оценка сохраняется у попытки.** Слой сборки записывает вердикт и состояние шага одной транзакцией. Оценка по рубрике остаётся предварительной.
- **Готовые схемы для ИИ-обработки.** Преподаватель выбирает схему по имени. Это позволяет проверить ответ по схеме уже в задаче 20. Общую защиту проверки схем портов и настроек нужно сделать отдельной задачей до ввода произвольных схем (открытый вопрос 29, ADR 0024).
- **Загрузка через API, выбор по номеру.** Автор выбрал этот вариант для задачи 19. API читает тело по частям, чтобы остановиться при превышении лимита, и проверяет, что указанный ученик принадлежит преподавателю.
- **`AGENTS.md` — главный файл правил, `CLAUDE.md` только подключает его.** Codex читает `AGENTS.md`, Claude Code — `CLAUDE.md`; одна копия правил не расходится.
- **Список задач — только `docs/roadmap.md`.** Он уже есть и по нему работает `next-task`; отдельный TASKS.md дублировал бы его.
- **Пуш, pull request и слияние — только по команде автора.** Так решил автор.
